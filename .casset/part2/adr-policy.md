# Architecture Decision Record Policy v1.0

## English

An ADR is required when a decision materially changes domain boundaries, data ownership, persistence strategy, infrastructure architecture, security trust boundaries, or agent permissions.

### ADR template
- Context
- Problem
- Decision
- Alternatives considered
- Consequences
- Migration/rollback plan
- Status

### Rule
Do not create ADRs for routine implementation choices. Do create them when future engineers or agents could reasonably make a different architectural choice.

## فارسی

هر تصمیمی که به‌صورت جدی Domain Boundary، مالکیت داده، Persistence، زیرساخت، Trust Boundary امنیتی یا سطح دسترسی Agentها را تغییر دهد باید ADR داشته باشد.

### قالب ADR
Context، Problem، Decision، Alternatives، Consequences، Migration/Rollback، Status.

### قانون
برای تصمیمات عادی ADR نسازیم؛ اما اگر یک Developer یا Agent آینده ممکن است درباره یک تصمیم معماری مهم برداشت متفاوتی داشته باشد، آن تصمیم باید ثبت شود.
