## ۲. باگ‌های واقعی که پیدا و رفع شدند

اینها مهم‌ترین بخش این نسخه‌اند. هیچ‌کدام «تغییر ظاهری» نبودند — هر کدام یک
نقص واقعی در محصولِ منتشرشده بود.

### ۲.۱ فونت سایت اصلاً لود نمی‌شد

`core/middleware.py` سیاست `style-src 'self'` را اعمال می‌کرد و همان سیاست،
استایل‌شیت Google Fonts را که `base.html` صدا می‌زد **بلاک می‌کرد**. یعنی
Vazirmatn روی هیچ مرورگری لود نمی‌شد و کل سایت با فونت پیش‌فرض سیستم رندر
می‌شد — چیزی که در بازبینی چشمی دیده نمی‌شود چون فونت جایگزین هم فارسی را
نشان می‌دهد.

**رفع:** فونت به‌صورت محلی میزبانی شد (`static/css/fonts.css`، سه زیرمجموعهٔ
woff2، زیرمجموعهٔ عربی preload). CSP به‌جای بازتر شدن، **سخت‌تر** شد:
`font-src 'self'`، `frame-ancestors 'none'` (به‌جز مسیر embed)،
`base-uri`/`form-action`/`object-src` قفل شدند.

این برای یک محصول ایرانی تصمیم درستی است حتی بدون باگ CSP: CDN گوگل از ایران
کند و بعضاً غیرقابل‌دسترس است.

### ۲.۲ XSS ذخیره‌شده در JSON-LD

`json.dumps` کاراکترهای `<`، `>` و `&` را escape نمی‌کند. یک انتشاردهنده
می‌توانست اثری با عنوان `</script><img src=x onerror=...>` بسازد و از بلوک
`<script type="application/ld+json">` فرار کند — روی صفحهٔ خود اثر و روی هر
صفحه‌ای که آن اثر را فهرست می‌کرد.

**رفع:** `core/structured_data.py` همان سه escape را اعمال می‌کند که
`django.utils.html.json_script` استفاده می‌کند. اینها escapeهای معتبر JSON
هستند، پس داده دقیقاً round-trip می‌شود — payload **escape** شده، نه حذف.
تست رگرسیون هر دو چیز را چک می‌کند: هیچ `<` خامی داخل عنصر نماند، **و** عنوان
هنوز درست decode شود.

### ۲.۳ کامنت چندخطی به‌عنوان متن قابل‌مشاهده رندر می‌شد

کامنت `{# … #}` در جنگو **فقط تک‌خطی** است. کشیدنش روی چند خط باعث می‌شود خط
اول ناپدید و **بقیهٔ خطوط روی صفحه چاپ شوند**. چهار قالب درگیر بودند، از جمله
`base.html` — یعنی نشتی روی **همهٔ صفحات** دیده می‌شد.

**رفع:** تبدیل به `{% comment %}` + دو نگهبان تست: یک اسکن روی سورس همهٔ
قالب‌ها، و یک ادعا که هیچ صفحهٔ رندرشده‌ای نشانگر قالب ندارد.

### ۲.۴ اسکرول افقی روی موبایل، در همهٔ صفحات

در عرض ۳۷۵ پیکسل، سند ۴۲۴ پیکسل بود. سه علت مستقل:

1. **هدر نمی‌توانست جمع شود.** `.search` یک flex item است و flex itemها
   `min-width: auto` دارند؛ عرض ذاتی یک input متنی حدود ۲۰ کاراکتر است. پس
   برند + جستجو + اکشن‌ها جا نمی‌شدند و هدر ۴۹ پیکسل سرریز می‌کرد.
2. **نوار پایین برای ۴ آیتم استایل شده بود و ۵ آیتم داشت.**
   `width: 25%` × ۵ = ۱۲۵٪، و یک flex item زیر min-content جمع نمی‌شود.
3. **ترک‌های گرید با `1fr` خام.** `1fr` یعنی `minmax(auto, 1fr)` و آن `auto`
   به **min-content** حل می‌شود — پس جدول عملکرد استودیو کل ستون را پهن
   می‌کرد، حتی با اینکه خودش داخل یک اسکرولر `overflow:auto` بود.

**رفع:** `min-width: 0` روی جستجو (و مخفی‌کردن جستجوی هدر زیر breakpoint
تبلت، چون نوار پایین ورودی اختصاصی Search دارد)، `flex: 1 1 0` روی آیتم‌های
نوار پایین، و `minmax(0, 1fr)` در **همهٔ** تعریف‌های گرید. به‌علاوه
`html { overflow-x: hidden }` به‌عنوان پشتیبان.

> در RTL این باگ خودش را پنهان می‌کند: صفحه بی‌صدا از محتوای خودش دور
> می‌اسکرولد، به‌جای اینکه یک نوار اسکرول آشکار نشان دهد.

### ۲.۵ تم روشن استانداردهای دسترسی‌پذیری را رد می‌کرد

هر جفت رنگ در برابر پس‌زمینهٔ واقعی‌اش اندازه‌گیری شد. تم تیره سالم بود؛ تم
روشن پنج شکست واقعی داشت:

| مورد | قبل | بعد |
|---|---|---|
| سفید روی دکمهٔ اصلی | **۲.۳۵:۱** | ۵.۹۶:۱ |
| اکسنت به‌عنوان متن | **۳.۱۸:۱** | ۵.۰۲:۱ |
| موجودی کیف پول (طلایی) | **۳.۰۹:۱** | ۵.۱۱:۱ |
| متن موفقیت | **۳.۳۱:۱** | ۵.۳۸:۱ |
| متن خطر | ۴.۹۱:۱ (مرزی) | ۶.۵۵:۱ |

**رفع:** «اکسنت به‌عنوان پس‌زمینه» از «اکسنت به‌عنوان متن» جدا شد (توکن جدید
`--accent-text` و `--purple-text`)، جوهر روی دکمهٔ نارنجی در تم روشن هم تیره
شد (نه سفید)، و رنگ‌های وضعیت تیره‌تر شدند.

### ۲.۶ مودال تایید، هندلر AJAX را دور می‌زد

`form.submit()` عمداً رویداد `submit` را شلیک **نمی‌کند** — پس هندلرهای
delegated در `app.js` هرگز اجرا نمی‌شدند و مرورگر مستقیم به یک endpoint JSON
پست می‌کرد. کاربر بعد از تایید حذف پلی‌لیست، روی یک صفحه JSON خام می‌افتاد.

**رفع:** `requestSubmit()` که رویداد را شلیک می‌کند و submitter را حفظ
می‌کند. به‌علاوه خود endpointها حالا برای یک POST فرم ساده redirect می‌دهند،
تا مسیر بدون-جاوااسکریپت مستقل درست باشد.

### ۲.۷ درگ‌اند‌دراپ پلی‌لیست به endpointی پست می‌کرد که آن شکل را نمی‌پذیرفت

`api_playlist_reorder` فقط جابه‌جایی تک‌پله‌ای می‌فهمید. هر درگ ۴۰۰ می‌گرفت.

**رفع:** حالا یک بدنهٔ JSON کامل `{"order": [...]}` هم می‌پذیرد، با چک‌های
مالکیتی که آن شکل لازم دارد: همهٔ idها باید مال خود کاربر و مال **یک**
پلی‌لیست باشند و تکراری نداشته باشند — یک لیست نیمه‌معتبر **کاملاً** رد
می‌شود، نه نیمه‌اعمال.

### ۲.۸ opt-out اعلان از یک attribute کش‌شده خوانده می‌شد

`recipient.notification_preference` یک reverse OneToOne است و جنگو نتیجه‌اش —
از جمله حالت «ردیف وجود ندارد» — را روی instance کش می‌کند. یک شیء کاربر که
قبل از نوشته‌شدن ردیف لود شده بود، از همان کش کهنه پاسخ می‌گرفت و opt-out
کاربر **بی‌صدا نادیده گرفته می‌شد**. این دقیقاً شکل یک درخواست واقعی است:
کاربر تنظیمات را ذخیره می‌کند و لحظاتی بعد چیزی به او اعلان می‌دهد.

**رفع:** کوئری مستقیم به‌جای خواندن از descriptor. توسط
`scripts/qa/journey_qa.py` پیدا شد، نه توسط تست واحد.

### ۲.۹ فایل‌های استاتیک هش نشده بودند + service worker با cache-first

ترکیب این دو یعنی **یک دیپلوی به کاربر نمی‌رسید** تا وقتی `VERSION` داخل
`sw.js` دستی بامپ شود — قدمی که بالاخره فراموش می‌شود.

**رفع:** `ManifestStaticFilesStorage` در production (هر فایل با هش محتوا نام
می‌گیرد)، و service worker فقط **مسیر** precache می‌کند نه مسیر asset — چون
آن مسیرها زیر نام‌های هش‌شده وجود ندارند. با یک اجرای واقعی `collectstatic`
تایید شد: ۱۸۷ فایل post-process شد و آدرس `@font-face` داخل `fonts.css` هم
درست به نام هش‌شده بازنویسی شد.

**نکتهٔ جانبی:** همین اجرا یک ارجاع مردهٔ `sourceMappingURL` در Chart.js
وندورشده را لو داد — فایل `.map` هرگز شیپ نشده بود، پس برای هر کسی که
devtools باز می‌کرد ۴۰۴ می‌داد.

### ۲.۱۰ رگرسیونی که خودم ساختم و گرفتم

منطق «JSON برای XHR، redirect برای فرم ساده» فقط به هدر `X-Requested-With`
نگاه می‌کرد، ولی `fetch` خود `app.js` آن هدر را نمی‌فرستاد. نتیجه: هر فراخوان
AJAX یک ۳۰۲ به صفحهٔ HTML می‌گرفت و روی `Unexpected token '<'` می‌مرد.

**رفع:** هر دو طرف، تا هیچ‌کدام به‌تنهایی بار را نبرد — `app.js` هدر را
می‌فرستد، و سرور `Accept: application/json` را هم می‌پذیرد.

## ۳. فیچرهای جدید

### ۳.۱ ورود با گوگل

پیاده‌سازی بومی در `accounts/oauth.py` — جریان authorization-code استاندارد
OpenID Connect.

**چرا django-allauth استفاده نشد:** allauth حدود ۴۰ پکیج provider، فضای نام
URL خودش، قالب‌های خودش، سه مدل اضافه و یک مجموعه migration می‌آورد — برای
**یک** provider، روی سایتی که کل رابط احراز هویتش مارک‌آپ فارسی سفارشی است.
جریان زیر تمام چیزی است که لازم داریم: حدود ۱۵۰ خط، بدون وابستگی جدید
(`requests` از قبل برای SMS و پرداخت هست)، و هر تصمیم امنیتی در همان فایل
دیده می‌شود.

**تصمیم‌های امنیتی:**

- **PKCE (S256)** حتی با اینکه این یک confidential client است. هزینه‌اش صفر
  است و کل کلاس حملهٔ interception کد را حذف می‌کند.
- **`state`** به session گره خورده؛ هر پاسخی با state ناهماهنگ رد می‌شود.
  بدون این، callback خودمان یک ورود آغازشده توسط شخص دیگر را می‌پذیرفت.
- **`nonce`** داخل ID token برمی‌گردد و چک می‌شود — جلوی replay یک توکن که
  برای session دیگری صادر شده را می‌گیرد.
- **امضای ID token محلی تایید نمی‌شود، و این عمدی است:** توکن در بدنهٔ یک POST
  مستقیم و TLS-authenticated به endpoint توکن گوگل می‌آید، در پاسخ به کدی که
  فقط ما داریم. مستندات خود گوگل تایید امضا را در همین حالت غیرضروری
  می‌داند. اما **همهٔ claimها** اعتبارسنجی می‌شوند: `iss`، `aud`، `exp`،
  `nonce`، `email_verified`.
- **ایمیل تاییدنشدهٔ گوگل کاملاً رد می‌شود.** پذیرفتنش یعنی هرکسی که بتواند
  یک حساب گوگل با آدرس دلخواه تاییدنشده بسازد، حساب کست متعلق به آن آدرس را
  تصاحب کند.
- **ترتیب تطبیق حساب:** اول `google_sub` (شناسهٔ تغییرناپذیر گوگل) تا تغییر
  آدرس جیمیل حساب کسی را بی‌صاحب نکند؛ بعد ایمیل، تا به حساب موجود وصل شود
  نه اینکه حساب تکراری بسازد.

**تنزل مرتب:** اگر `GOOGLE_OAUTH_CLIENT_ID`/`SECRET` تنظیم نشده باشند، دکمه
اصلاً نشان داده نمی‌شود و ورود با موبایل/رمز کار می‌کند. برخلاف SMS و پرداخت،
اینجا گارد fail-fast در prod نیست — چون محصول بدون گوگل کار می‌کند.

### ۳.۲ قانون انتشاردهنده

**قانون محصولی:** هرکس یوزرنیم عمومی انتخاب کند انتشاردهنده است — و
انتشاردهنده باید شمارهٔ موبایل تاییدشده داشته باشد.

**کجا اعمال می‌شود — و چرا آنجا:** آپلود **پیش‌نویس** برای هر حساب واردشده
باز است. پیش‌نویس خصوصی و بی‌ضرر است. چیزی که گیت می‌خورد **ارسال برای
بررسی** است، یعنی لحظه‌ای که محتوا به سمت عمومی‌شدن می‌رود
(`uploads/views.py::submit_track`). گیت‌کردن در زمان آپلود، آدم‌ها را از
آماده‌کردن کارشان قبل از تکمیل ثبت‌نام منع می‌کرد، بدون هیچ سود امنیتی.

تعریف در یک جا زندگی می‌کند: `UserProfile.can_publish` و
`publish_blockers()`. صفحهٔ `creator_apply` همان چک‌لیست را به کاربر نشان
می‌دهد، تا هیچ‌وقت بعداً به دیوار نخورد.

**فیچر جدیدی که لازم شد:** تایید شمارهٔ موبایل برای حسابی که **از قبل وارد
شده** (`/account/phone/`). جریان OTP قبلی فقط برای حالت خارج‌از‌حساب بود —
آنجا شمارهٔ منطبق یعنی «وارد آن حساب شو»، که برای کاربر واردشده یک تعویض حساب
است، نه یک تایید.

### ۳.۳ تنظیمات اعلان

مدل `NotificationPreference` با **یک نقطهٔ اعمال** در
`notifications/services.py::_allowed`. خاموش‌کردن یک گزینه واقعاً جلوی نوشتن
ردیف را می‌گیرد؛ فیدی که همچنان رشد می‌کند فیلتر نمی‌شود.

دو تصمیم عمدی:

- **نبودن ردیف = همه‌چیز روشن.** معرفی این مدل نباید حساب‌های موجود را
  بی‌صدا ساکت کند.
- **`track_approved` و `track_rejected` قابل خاموش‌کردن نیستند.** اینها
  نتیجهٔ بررسی‌اند، نه اعلان اجتماعی؛ اجازهٔ ساکت‌کردنشان محصول را با کاربر
  نادرست می‌کرد.

### ۳.۴ بازیابی رمز عبور

با viewهای خود جنگو (تولید و انقضای توکن چیزی است که هرگز نباید دستی نوشت)؛
فقط قالب‌ها و مقصدهای redirect از ماست.

## ۴. سیستم طراحی — Orange Noir v2

### ۴.۱ توکن‌ها

`static/app.css` تنها منبع حقیقت است. مقیاس کامل تایپ، فاصله، شعاع، سایه و
حرکت، به‌علاوهٔ سه‌تایی‌های کانال (`--accent-rgb` و…) که هر سطح شفاف را
قابل‌تم‌شدن می‌کنند.

**تم روشن حالا یک تم واقعی است**، نه یک پچ. hack قبلی در `base.html` که فقط
رنگ هدر را عوض می‌کرد و بقیهٔ متن‌ها را سفید نگه می‌داشت، حذف شد.

**تفکیک مهم:** «رنگ به‌عنوان پس‌زمینه» و «رنگ به‌عنوان متن» دو مسئلهٔ متفاوت‌اند.
`--accent` برای fill است، `--accent-text` برای متن — روی زمینهٔ تیره یک تینت
روشن و روی زمینهٔ روشن یک تن عمیق و اشباع.

### ۴.۲ لایه‌ها

```
static/css/fonts.css       فونت self-host (سه زیرمجموعه)
static/app.css             توکن‌ها + لایهٔ پایه (میراث، حفظ‌شده)
static/css/casset-ui.css   لایهٔ کامپوننت (۲۴ بخش)
static/css/cassette.css    هویت پلیر
```

### ۴.۳ آیکون

اسپرایت SVG درون‌خطی، از ۲۴ به **۸۱** نماد. صفر درخواست شبکه، صفر وابستگی،
و هر نماد `currentColor` را ارث می‌برد پس رایگان تم می‌شود. ایموجی‌های خام
پروفایل عمومی (🌐📷✈️) با آیکون واقعی جایگزین شدند — تنها جایی که سیستم آیکون
می‌شکست.

### ۴.۴ پلیر کاست

اسم برند یعنی نوار کاست؛ هیچ رقیبی برندش به یک شیء فیزیکی گره نخورده. پلیر
جایی است که برند واقعاً زندگی می‌کند:

- دو **قرقرهٔ چرخان** که با `animation-play-state` کنترل می‌شوند، نه با
  اضافه/حذف کل انیمیشن — یک پلیر متوقف هیچ هزینه‌ای ندارد و فقط `transform`
  انیمیت می‌شود (compositor-only).
- **برچسب کاغذی** با چرخش ۱ درجه — همان جزئی که پلیر را در یک نگاه
  غیرقابل‌اشتباه می‌کند.
- **اسکرابر رنگ‌نوار** (`--tape`) با fill نارنجی.
- شمارندهٔ زمان با `tabular-nums` و tracking بازتر.
- `prefers-reduced-motion` کاملاً رعایت می‌شود.

قرارداد `data-*` که `app.js` رویش سوار است، دست‌نخورده ماند.

### ۴.۵ انضباط

**صفر `style=`** در قالب‌ها (از ۴۰۵)، به‌جز یک مورد که واقعاً داینامیک است
(عرض نوار پیشرفت که از سرور می‌آید) — دقیقاً همان استثنایی که در سند طراحی
تعریف شده بود.

## ۵. تصمیم‌های معماری

### ۵.۱ Vite / Alpine / htmx اضافه نشدند

سند طراحی اینها را پیشنهاد داده بود. **اضافه نشدند، و این یک تصمیم آگاهانه
است که باید صریح گفته شود.**

افزودن Vite یعنی: وابستگی Node روی سرور production، یک مرحلهٔ build در CI،
و پکیج `django-vite` — برای سایتی که دو فایل استاتیک دستی دارد. ریسک عملیاتی
است بدون سود کاربری. چیزی که Vite قرار بود بدهد (cache-busting، سازمان‌دهی
کد) از راه‌های ارزان‌تر گرفته شد:

- **cache-busting** → `ManifestStaticFilesStorage` که خود جنگو دارد
- **سازمان‌دهی** → تفکیک CSS به لایه‌های صریح و `casset-ui.js` جدا
- **htmx** → همان مسیرهای `fetch` که از قبل کار می‌کردند
- **Alpine** → progressive enhancement با event delegation موجود

هدف صریح صاحب پروژه «نسخهٔ بدون باگ، بدون خطر امنیتی، قابل ارائه برای ۱۰۰۰
کاربر» بود. کم‌ترین قطعات متحرک، بهترین خدمت به آن هدف است.

اگر بعداً تیم فرانت‌اند مستقل بگیرد، این تصمیم قابل بازبینی است — هیچ‌چیز در
این نسخه مانعش نمی‌شود.

### ۵.۲ ناوبری

خانه · جستجو · پرطرفدارها · کتابخانه · استودیو · داشبورد · اعلان‌ها ·
تنظیمات — با منوی آواتار برای پروفایل/کیف پول/خروج. زیر breakpoint تبلت،
جستجوی هدر مخفی می‌شود چون نوار پایین ورودی اختصاصی دارد.

### ۵.۳ مذاکرهٔ محتوا

چند endpoint هم پشتیبان یک `fetch` هستند و هم یک `<form>` واقعی. هر دو سیگنال
(`X-Requested-With` و `Accept`) بررسی می‌شوند، تا مسیر بدون-جاوااسکریپت هرگز
روی JSON خام نیفتد و مسیر AJAX هرگز redirect نگیرد.

## ۶. سئو

- **Sitemap** برای آثار، شوها و پروفایل‌های دارای یوزرنیم. فقط محتوای عمومی
  و تاییدشده — یک URL در sitemap که ۴۰۴ بدهد به گوگل یاد می‌دهد به بقیهٔ
  URLهای ما هم بی‌اعتماد باشد.
- **robots.txt** تولیدشده (نه فایل استاتیک) — چون خط `Sitemap:` باید هاست
  زنده را حمل کند.
- **JSON-LD** با نوع schema که از `content_type` انتخاب می‌شود:
  `MusicRecording` / `PodcastEpisode` / `AudioBook` / `VideoObject`. یک
  پادکست که به‌عنوان MusicRecording مارک‌آپ شود از نبود مارک‌آپ بدتر است.
  `contentUrl` هرگز برای اثر غیرعمومی منتشر نمی‌شود.
- **عنوان یکتا** برای هر صفحه، زیر ۶۰ کاراکتر (نقطهٔ برش گوگل). قبلاً اکثر
  صفحات رشتهٔ «Casset» را حمل می‌کردند.
- **canonical** روی صفحات پارامتردار؛ `/@username/` به `/handle/` ریدایرکت
  می‌شود تا یک نفر یک URL کانونیکال داشته باشد.
- **og:image** همیشه موجود — کارت پیش‌فرض برند ۱۲۰۰×۶۳۰ ساخته شد. پیش‌نمایش
  لینک بدون تصویر مثل لینک خراب خوانده می‌شود.

## ۷. PWA

- ست کامل آیکون (۱۹۲/۵۱۲ معمولی و maskable) + `apple-touch-icon`
- `manifest.webmanifest` با `id`، `scope`، `shortcuts`، متادیتای فارسی و `dir: rtl`
- **service worker بازنویسی‌شده** با استراتژی به‌ازای نوع منبع:

| منبع | استراتژی | چرا |
|---|---|---|
| استاتیک | cache-first | نام‌ها content-hashed‌اند، پس امن است |
| صفحات HTML | network-first | یک فهرست آثار کهنه بدتر از کمی کندی است |
| API (GET) | stale-while-revalidate | رنگ فوری، تازه در دفعهٔ بعد |
| صوت/ویدیو | **هرگز cache نمی‌شود** | یک اثر ده‌ها مگابایت است و بقیه را بیرون می‌اندازد؛ کش HTTP خود مرورگر range request را بهتر مدیریت می‌کند |
| POST | اصلاً لمس نمی‌شود | کش نباید بین یک لایک و سرور بایستد |

- صفحهٔ آفلاین اختصاصی
- پرامپت نصب برندشده که فقط بعد از چند بازدید نشان داده می‌شود و پس از رد
  دیگر برنمی‌گردد
