## ۱. خلاصهٔ اجرایی

خبر خوب: پروژه واقعاً در وضعیت خوبی است. ترسی که در درخواست اولیه بود («فایل‌های
نامرتب»، «schedule های عجولانه»، «مستندات ناکارآمد») **در عمل تأیید نشد**. مستندات
`.casset/` منظم، به‌روز و به‌شدت دقیق‌اند؛ برنچ‌ها همه یا از قبل merge شده‌اند یا
منسوخ و بی‌خطرند؛ کد فاقد کد نمادین/stub قابل‌توجه است. تنها مشکل واقعی که پیدا شد
یک آلودگی سطحی line-ending (CRLF) در working tree بود که باعث شده `git status`
به‌اشتباه ۲۳۵ فایل را «modified» نشان دهد — هیچ‌کدام تغییر محتوایی واقعی نداشتند.

## ۲. یافتهٔ اصلی: چرا همه‌چیز "modified" نشان داده می‌شد

بررسی با `git diff -b`/`--ignore-all-space` روی هر ۲۳۵ فایل «modified» نشان داد
**مجموع خطوط تغییریافته صفر بود** — یعنی صرفاً پایان خط از LF (نسخهٔ کامیت‌شده) به
CRLF تغییر کرده (احتمالاً از ویرایش/ذخیره روی ویندوز بدون تنظیم `core.autocrlf`).
هیچ کد یا سندی واقعاً دستکاری نشده بود. راه‌حل: `git checkout -- .` (دستور کامل در
بخش ۶).

**دو فایل واقعاً جدید و untracked** هم پیدا شد که کار واقعی هستند، نه زباله:
- `accounts/management/commands/generate_avatars.py` + `__init__.py`ها
- `scripts/generate_avatars.py`

اینها اسکریپت تولید آواتار اولیهٔ کاربران‌اند (initials + رنگ تصادفی) — باید
`git add` و کامیت شوند، نه پاک شوند.

## ۴. صف کار خودکار (`task-queue.md`)

۴ آیتم از ۵ آیتم `⬜ pending` قبلی در این ممیزی بررسی و بسته شدند (جزئیات در
`task-queue.md` بخش آرشیو):
- پاکسازی ریشهٔ مخزن → از قبل کامل بود، `.gitignore` همین حالا پوشش می‌دهد.
- مقایسهٔ `pyproject.toml`/`requirements_current.txt` → فایل دوم اصلاً وجود ندارد، منتفی.
- اندازه‌گیری پوشش تست → **در sandbox این ایجنت ممکن نشد** (پایتون محیط ۳.۱۰ است،
  پروژه ≥۳.۱۲ نیاز دارد؛ `.venv/` هم native ویندوزی است). PYMN باید خودش
  `coverage run --source=. manage.py test && coverage html` را روی سیستم واقعی
  اجرا و عدد را در `current.md` جای عدد قدیمیِ ۸۱٪ ثبت کند.
- تایید حذف `config/settings.py` → دوباره تأیید شد، بسته.

یک آیتم باز مانده (بررسی fail-fast بودن `SECRET_KEY`/`PLAY_IP_SALT`/`PLAY_UA_SALT`
در `config/settings/base.py`) نیاز به بازبینی مستقیم کد در یک نشست جداگانه دارد.

## ۶. اقدامات لازم — این‌ها را خودت روی ویندوز (PowerShell) اجرا کن

این ایجنت روی این ریپازیتوریِ mount‌شده از ویندوز اجرا می‌شود؛ هر عملیات
نوشتنی گیت (`add`/`commit`/`checkout`/حذف برنچ) با خطای
`Unable to create '.git/index.lock': File exists` / `unable to unlink` شکست
می‌خورد، چون این mount اجازهٔ unlink/rename نمی‌دهد (محدودیت سطح sandbox، نه
مشکل ریپازیتوری). این ماندگار است، نه یک قفل یک‌بارهٔ قابل‌حذف. پس دستورات زیر
را خودت در PowerShell/Git Bash واقعی روی ویندوز، داخل
`D:\Casset.ir\casset-django` اجرا کن:

```powershell
# 0) اگر فایل قفل باقی‌مانده از تلاش این ایجنت وجود دارد، پاکش کن (بی‌خطر):
Remove-Item .git\index.lock, .git\index.lock.old -ErrorAction SilentlyContinue

# 1) رفع آلودگی CRLF — بدون از دست رفتن هیچ تغییر واقعی (تأیید شد: diff -b == 0)
git checkout -- .
git status --short   # باید کاملاً خالی باشد به‌جز دو فایل untracked زیر

# 2) اضافه‌کردن اسکریپت‌های واقعی جامانده
git add accounts/management/commands/generate_avatars.py `
        accounts/management/commands/__init__.py `
        accounts/management/__init__.py `
        scripts/generate_avatars.py
git commit -m "feat(accounts): add avatar generation management command and script"

# 3) پاکسازی برنچ‌های محلی زائد (سوییچ به master چون HEAD فعلی دقیقاً برابر آن است)
git checkout master
git branch -d feat/orange-noir-v2
git branch -d stabilization/v1-baseline
git branch -d auto/2026-08-20-verify-settings-cleanup

# 4) آرشیو ایمن قبل از حذف — یک تگ آرشیوی از release/v2 قدیمی بگیر (اختیاری ولی توصیه‌شده)
git tag archive/release-v2-dec2025 origin/release/v2

# 5) حذف برنچ‌های ریموت منسوخ/merge‌شده
git push origin --delete Codex
git push origin --delete docs/part-2-engineering-foundation
git push origin --delete release/v2
git push origin --delete codex/upgrade-genre-to-v2
git push origin --delete feat/orange-noir-v2   # اگر می‌خواهی نگه‌داری، این خط را رد کن

# 6) push نهایی master (شامل کامیت آواتار بالا)
git push origin master
git push origin archive/release-v2-dec2025

# 7) اندازه‌گیری واقعی پوشش تست (چون در sandbox این ایجنت ممکن نبود)
coverage run --source=. manage.py test
coverage html
# عدد نهایی را در .casset/state/current.md جای «۸۱٪» قدیمی جایگزین کن
```

پس از اجرا، فقط کافی است به من بگویی «انجام شد» تا `.casset/state/current.md` و
این سند را با نتیجهٔ نهایی (شمارهٔ کامیت، عدد پوشش تست جدید) به‌روزرسانی کنم.
